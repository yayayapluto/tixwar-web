GAMBARAN PROYEK

Kenapa flash sale itu sulit

Masalah

  • Ribuan pengguna berebut stok terbatas dalam hitungan detik.
  • Satu kursi tidak boleh terjual dua kali.
  • Klik berulang dan retry dapat membuat order ganda.
  • Satu dependency mati tidak boleh mematikan seluruh sistem.

Janji sistem

  • Nol oversell. Stok dijaga atomik di Redis.
  • Tanpa order ganda. Idempotency-Key di tiap mutasi order dan pay.
  • Tetap jalan. Pembayaran async, circuit breaker, dan outbox.

MODUL API

Modul-modul API

Modular monolith: satu codebase, tiga proses (API, worker, outbox-publisher). Bukan microservices.

auth

Login, refresh token, lupa dan reset password. JWT access 15 menit, refresh 7 hari.

events

CRUD event dan statistik. SSE stream untuk stok dan status event.

orders

Buat dan batalkan order. Gerbang stok atomik di Redis.

payments

Terima permintaan bayar, lalu serahkan ke worker. Status order mengikuti hasil tagihan.

apikeys

Kunci API untuk klien eksternal, dengan expiry opsional dan lastUsedAt.

debug

Load generator, chaos injection, dan trace stream SSE.

DATA LAYER

Data layer: tiga penjaga konsistensi

MongoDB 7

  • Sharded via mongos, shard key userId.
  • Order dan event outbox ditulis dalam satu transaksi.
  • Order tanpa event tidak akan terjadi.

Redis 7

  • Atomic stock gate: Lua reserve stock:{tierId}.
  • Cache event dan stok.
  • Channel order:{id} untuk status order via SSE.

BullMQ + outbox

  • Outbox polling dengan lease.
  • At-least-once, jobId deterministik.
  • Antrean: order, payment, notification, webhook, expiry, dlq.

PEMBAYARAN

Pembayaran async: bayar tidak pernah menunggu gateway

  1. POST /v1/orders/{id}/pay hanya mengembalikan 202 QUEUED.
  2. Event payment.requested masuk outbox, lalu publisher enqueue ke BullMQ.
  3. Worker menagih mock-gateway lewat circuit breaker.
  4. Berhasil: order.paid, tiket + QR ke MinIO, order.confirmed.
  5. Bayar gagal: stok tidak dilepas. Stok hanya dilepas saat order kedaluwarsa atau dibatalkan.

KEAMANAN

Auth dan API keys

Auth (JWT)

  • Access 15 menit, refresh 7 hari.
  • Refresh memakai rotasi dan deteksi reuse.
  • Login menerima email atau identifier admin.
  • Lupa password: token sha256, 1 jam, sekali pakai.

API keys

  • Expiry opsional: 7, 30, atau 90 hari.
  • Kunci kedaluwarsa mengembalikan 401.
  • lastUsedAt tercatat di tiap pemakaian.
  • Kunci dikelola dari halaman API keys.
