# AGENTS.md

TixWar frontend. Flash-sale ticketing web app for the TixWar API (`../api`). See `README.md` for
the full guide; this file is the working contract for coding agents.

## Stack

- Vite + React 19 + TypeScript (strict, project references)
- TanStack Router (file-based, `src/routes/`, plugin-generated tree)
- TanStack Query (shared client in `src/lib/queryClient.ts`)
- Tailwind CSS v4 + shadcn/ui (CSS variables, light/dark theme)
- Biome (lint + format)
- Bun (package manager, scripts)
- `@hey-api/openapi-ts` (generated API client in `src/lib/client/`)

## Commands

```bash
bun install
bun run dev          # dev server, http://localhost:3000
bun run lint         # biome check .
bun run typecheck    # tsc -b --noEmit
bun run build        # tsc -b && vite build
bun run preview      # serve dist/
bun run api:gen      # regenerate client + sync docs/api-types.d.ts from ../api
```

Run `lint`, `typecheck`, and `build` before every commit. Do not proceed if any is red.

`api:gen` requires a sibling API checkout; it reads `../api/docs/openapi.json` and
`../api/docs/api-types.d.ts` (generated there by `just api-types`).

## Environment

`VITE_API_BASE_URL` sets the API origin; default `http://localhost:8080` (`src/lib/api.ts`).
Copy `.env.example` to `.env`. The API must allow the web origin through `CORS_ORIGINS`.

## Folder structure

```
src/
  components/ui/     shadcn primitives (button, input, card, select, ...)
  components/        shared presentational (status.tsx: loading/empty/error)
  features/<name>/   per-feature queries, hooks, forms
                     auth, api-keys, debug, events, orders, payments, realtime, theme, tickets
  routes/            TanStack Router file-based routes
  lib/               generated client, client config, auth, errors, sse, query client, utils
docs/api-types.d.ts  API types copied from ../api/docs/api-types.d.ts
scripts/sync-types.ts
```

Path aliases: `@/*` → `src/*`, `@api-types` → `docs/api-types`.

## Routes and access

| Route                                                           | Guard                                                                     |
| --------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `/`, `/events`, `/events/$eventId`, `/login`, `/register`       | public                                                                    |
| `/orders`, `/orders/$orderId`, `/tickets`, `/tickets/$ticketId` | `requireCustomer` (any logged-in user except admin; admins are view-only) |
| `/api-keys`                                                     | `requireAuth` (any logged-in user; the API scopes keys per owner)         |
| `/settings`                                                     | `requireAuth`                                                             |
| `/debug/stream`                                                 | `requireAdmin`                                                            |

`requireAuth` redirects to `/login?redirect=<href>`; `requireAdmin` also requires
`session.user.role === 'admin'`; `requireCustomer` requires a logged-in non-admin
session and redirects admins to `/`. Guards live in `src/features/auth/route-guard.ts`.
Admins are view-only: no Orders/Tickets menu or routes, and no Buy button on event
detail (they keep Events, API keys and Debug).

## Rules

- Use the generated client (`@/lib/client`) for every API call. Never write manual `fetch`.
  Sole exception: fetching the ticket QR image blob in `src/routes/tickets/$ticketId.tsx`.
- Never invent endpoints. Only call functions generated from the API docs.
- Domain types come from `@api-types` (`components['schemas']['Order']`, `paths['/v1/orders']['post']`).
- Order creation and payment require `Idempotency-Key`; use `newIdempotencyKey()` from
  `src/lib/utils.ts`.
- All TanStack packages are pinned to exact versions in `package.json`.
- `.env` holds `VITE_API_BASE_URL`. Never commit secrets. Use `.env.example` as template.
- `src/lib/client/**` and `src/routeTree.gen.ts` are generated — do not hand-edit.
- `docs/api-types.d.ts` is generated by `api:gen` — do not hand-edit.

## Client interceptor

`src/lib/api.ts` configures the single client instance at startup (imported in `main.tsx`):

- Sets `baseUrl` from `VITE_API_BASE_URL` and injects `Authorization: Bearer <accessToken>`.
- On 401: single-flight refresh, retries the request once, logs out if refresh fails. Auth
  endpoints are excluded from the retry whitelist.
- On 429: maps `Retry-After` into `ApiError.retryAfterSeconds`.
- Maps every error to one type: `ApiError` (`src/lib/errors.ts`), with `status`, domain `code`,
  `title`, `detail`, `requestId`, field `errors`, and optional `retryAfterSeconds`.

Session state lives in `localStorage` (`tixwar.session`) through `src/lib/auth.ts` and is consumed
with `useSession()` (`useSyncExternalStore`). Theme state is in `src/features/theme`.

## Query and realtime conventions

- Query keys follow `['events', filters]`, `['event', id]`, `['event', id, 'stats']`, `['orders', status]`,
  `['order', id]`, `['tickets']`, `['ticket', id]`, `['api-keys']`.
- `queryClient` defaults: `staleTime` 30s; retry twice except 401/403/404, `SOLD_OUT`,
  `ORDER_EXPIRED`; 429 retries up to two attempts.
- Mutations invalidate the affected list and detail keys.
- Streaming hooks use `useSse` (`src/lib/sse.ts`) with a generated SSE call and invalidate or patch
  query data on `message` frames. Do not duplicate connection logic; let the generated client
  reconnect.
- `useStockStream` → `stock.released`; `useOrderStream` → `order.status`; `useDebugStream` → all.

## State conventions

Every feature screen must render three states: loading (skeleton), empty, error. Use
`src/components/status.tsx` (`ListSkeleton`, `EmptyState`, `ErrorState`). Show
`ApiError.retryAfterSeconds` when present and render domain-code messages for sale and limit errors.

Mobile-first. Respect `prefers-reduced-motion`. Keyboard navigation and ARIA labels required (icon
buttons need `aria-label`). No decorative/section-separator comments — only comments that explain
non-obvious logic.
